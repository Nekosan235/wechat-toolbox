# 小猫拌饭的工具箱 · 图片与 GIF 透明素材

纯本地微信小程序。图片和 GIF 不上传服务器；无登录、广告、付费或第三方依赖。

代码公开供学习与交流，当前为持续开发版本。仅处理自己拥有或获准编辑的素材，尊重著作权与署名。公开源码不等于小程序已上线，发布仍需自己的账号、备案与平台审核。

## 下载与运行

1. 安装微信开发者工具，克隆本仓库：`git clone https://github.com/Nekosan235/wechat-toolbox.git`，也可下载 ZIP 并解压。
2. 将 `project.config.example.json` 复制为同目录下的 `project.config.json`。
3. 在配置中将 `appid` 换成自己的小程序 AppID，再用开发者工具导入项目根目录，选择「不使用云服务」。示例中的 `touristappid` 仅用于游客体验，真机预览及发布需有效账号和 AppID。
4. 点击编译，从内置示例开始试用。不需要部署服务器，也不需要安装业务依赖。

本机 `project.config.json` 和 `project.private.config.json` 不进入版本管理；仓库只提供通用配置示例，不包含维护者的 AppID 与个人开发偏好。AppID 不是密码，AppSecret、访问令牌与服务器密钥则绝不能提交。

## 项目结构

- `pages/home`：工具箱首页。
- `pages/index`：静态图片去白底与手动精修。
- `pages/gif`：GIF 预览、逐帧精修与导出。
- `components/tool-drawer`：共享工具抽屉。
- `utils`：去白算法、视图变换、画笔及 GIF 编解码。
- `tests`：像素算法、编解码、页面交互与布局验证。

新增功能与问题反馈可通过 GitHub Issues 交流，开发约定见 [CONTRIBUTING.md](CONTRIBUTING.md)。项目采用 [MIT 许可证](LICENSE)：允许使用、修改、分发和商用，须保留版权与许可说明；软件按原样提供，不作担保。代码许可不授予所处理图片、GIF 或其他素材的权利。

## 使用

1. 微信开发者工具打开本目录，点击编译。
2. 首页选择「图片去白底」或「GIF 逐帧编辑」，也可从「所有工具」抽屉切换。
3. 默认仅移除与图片边界连通的白底，保留封闭的白色主体细节。
4. 调整去白底强度；需要去掉主体内部的白色时开启「全图去白」。
5. 切换原图／效果和预览背景；在效果图上用擦除／还原画笔修整，可撤销上一笔。
6. 点击「保存透明 PNG」。相册授权必须由用户在手机上完成。

棋盘格和预览背景只用于显示，不会进入导出文件。导出保留透明通道。

## 放大精修与取色画笔

两种编辑页都支持1～8倍预览缩放，点击放大／缩小／适应。放大后选择「移动」单指拖动画面，定位细节后切回擦除、还原或画笔。当前版本使用按钮缩放，不支持双指捏合；缩放、拖动只影响预览，不改变输出像素尺寸，也不会把画面裁切后导出。

要在主体内部手工遮盖水印，先选择「取色器」，点击附近合适的颜色，自动进入「画笔」；调小笔刷涂抹。取色从当前编辑像素读取，自动去白的透明区回退取原图像素；画笔写入选定RGB与不透明像素，不把主体擦成透明。每笔的颜色独立保存，撤销可以恢复，GIF仍只修改当前帧。适用于纯色或简单色块，不能自动恢复水印遮住的复杂纹理，不是AI内容修复。

## GIF 使用

将原始 GIF 作为文件发给文件传输助手，在 GIF 页选择聊天文件；也可试用本地生成的示例。拖动进度条、上一帧／下一帧定位，播放会按原帧延时预览；涂抹自动暂停。笔画只影响当前帧，撤销也只撤销当前帧；调整去白强度保留笔迹。

修改后旧导出立即失效，点击「生成透明 GIF」会逐帧写入所有修改、保留延时及循环信息，可随时取消且不丢编辑记录。推荐「发送 GIF 文件」保留动画；相册保存仅作为兼容选项，微信官方并未承诺所有手机保存后仍为动画，请检查结果。

## iOS 风格工具抽屉

首页与两种编辑页统一浅灰背景、白色分组、系统字体、蓝色主操作、分段控件与安全区。点击「所有工具」打开底部抽屉，上拉手柄展开、下拉收起／关闭，也可点击明确的展开／关闭按钮。

后续的智能抠图、视频去白和内容修复已预留入口，标注「待开放」且不能进入。未来工具从 `utils/tool-catalog.js` 统一登记，新增可用页后填写 route 并加入 app.json。

视觉依据与Apple官方HIG参考见 DESIGN.md；这是微信原生实现，不是 UIKit 或 Apple 官方应用。

## 范围

- 静态图片上限 10 MB，长边超过 2048 像素会等比例缩小。
- 适合白底商品图、图标、插画；不是 AI 主体识别。
- 白色主体与边缘白底直接相连时仍可能被移除。可降低强度；复杂图留给后续智能抠图。
- GIF 输入最多8 MB、1024×1024、60帧、15秒，总逻辑像素最多3200万；输出长边最多480像素，文件最多20 MB。解码采用顺序合成及3帧缓存，不在内存保留所有RGBA。
- GIF只有全透明／不透明，半透明边缘会简化；多色动画导出可能量化颜色。罕见GIF文本绘制扩展不支持，会明确报错。
- 擦除水印会让该区域透明，不会补回原画面。仅处理自己有权编辑的素材；智能主体识别、视频与内容修复尚未实现。
- 每张静态图片／每个GIF帧最多100笔，每笔最多1024点；GIF全片最多1000笔。还原恢复原始RGBA，包括原始透明度。
- 原始透明像素会保留；每次调整从原始像素重新计算，避免反复损伤。
- 正式提审前，在小程序后台完善隐私保护指引，声明选择图片及保存相册用途；完成备案和平台要求。

## 验证

使用 Node.js 18 或更新版本执行 `node --test tests/*.test.js`，核心测试无需安装 npm 依赖。安装 FFmpeg 可运行独立解码交叉验证；缺少 FFmpeg 时相应测试会跳过。
测试包含GIF编解码、画笔、独立FFmpeg解码交叉校验、页面操作及抽屉导航。WXML/WXSS通过微信独立编译器检查；`tests/render-ui-preview.cjs` 是可选的布局验证，需要自行提供 Playwright 和 Edge，可通过 `TOOLBOX_PLAYWRIGHT_PATH` 指定已有 Playwright 模块路径、通过 `TOOLBOX_BROWSER_CHANNEL` 选择浏览器通道，对源模板进行320/390像素布局检查。它不是微信模拟器；小程序运行不需要这些工具。

上一版静态图片选图／保存已由用户手机确认；新增GIF、画笔与抽屉尚未真机验收。手机扫码检查Canvas触摸位置、抽屉覆盖及滚动、相册授权、GIF文件发送和动画保留。这些平台行为无法仅靠自动化mock测试验证。

后续可独立接入云开发和 AI 抠图，第一版不消耗服务器或付费 API。
